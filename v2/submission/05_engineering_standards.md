# 5. Engineering Standards

This section presents the standards the project follows, in risk management, least privilege and network addressing. For each, it states what the standard asks, how the project meets it and, where the project departs from it, why.

## 5.1 Risk management

The threat model follows ISO 31000 (International Organization for Standardization, 2018), which fixes the order of a risk-management process: establish the context, identify risks, analyse and evaluate them, then treat and monitor them. Because the standard prescribes no technique for identifying risks, the project uses STRIDE (Shostack, 2014) for that step, as Section 8 describes. The one departure concerns impact. Instead of a generic scale, impact is rated on the value of the household's assets, because no general scale has a level for defeating a safety function in a home.

## 5.2 Least privilege

The standard closest to the platform's problem is ETSI EN 303 645, the European baseline for consumer IoT security, whose scope names "connected home automation and alarm systems, especially their gateways and hubs" (ETSI, 2024, Section 1). Its provision 5.6-7 states that "software should run with least necessary privileges" (ETSI, 2024, Provision 5.6-7), and NIST SP 800-53 sets the same principle as control AC-6 (Joint Task Force, 2020). Home Assistant's integration model does the opposite, since every integration runs with all of the platform's privileges. The framework meets the provision by giving each integration only what its manifest declares, and applies it to itself, since the mediator acts on the platform as a user without administrator rights. One departure from least privilege is stated. Applied to system calls, the principle would allow an integration only the calls it needs; the filter instead blocks calls known to be dangerous and allows the rest. Which calls an integration makes depends on the interpreter and on every library it loads, and changes with each update, so a list of needed calls could not be written in advance without breaking integrations. Least privilege is therefore applied to what an integration can reach rather than to the calls it makes: the other isolation features narrow what the remaining calls can act on, although a list of dangerous calls can be incomplete.

## 5.3 Network addresses

Two address standards define the household's own network. RFC 1918 reserves the private ranges that home routers give the devices in a house (Rekhter et al., 1996), and RFC 6598 reserves a range that internet providers use between a household and the internet, and that some private overlay networks also use (Weil et al., 2012). The gate checks the address a granted name resolves to, not only the name, and refuses both ranges for any grant of a public host, together with the loopback address of the computer running Home Assistant, link-local addresses and every other address reserved for special use. Only a separate grant of the home network opens the private ranges, and even that grant leaves the shared range, loopback and link-local addresses closed. A grant for a public host therefore cannot be turned into a route to the household's router or to the computer running Home Assistant.
