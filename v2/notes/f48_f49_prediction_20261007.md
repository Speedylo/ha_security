## F48: the supervisor, in a suite of its own

**`selftest_supervise.py`**, the 27th suite. Needs (A) up, like `selftest_real_platform`. It starts
`confine.supervise` on `experiments/flood/demo_flood` as an installation would (a separate process,
its own audit directory), acts as a person in (A) does, and checks, in order:

1. it starts: run 1's sandbox pid is alive and its cgroup (`sup-demo_flood-<pid>-1`) exists;
2. **cut-off kills the sandbox**: pressing the switch floods, the mediator cuts it off, and within
   15 s the sandbox's pid is gone and its cgroup removed;
3. **Repairs restarts it**: the fix flow completes, run 2 starts with a new live pid, and the durable
   log holds exactly one `cutoff` and one `reinstate`;
4. **(A) restarting brings it back** (F29): `house_a restart`; the supervisor reports (A) went away
   and came back, and run 3 starts;
5. **a predecessor's sandbox is cleared** (F30): the supervisor is SIGKILLed with run 3 running; a
   second supervisor reports clearing one cgroup, run 3's pid is gone, and its own run 1 starts;
6. **a sandbox that exits by itself is not restarted**: the second supervisor's sandbox is SIGKILLed;
   it reports "exited by itself" and no further run starts within 10 s;
7. **it stops cleanly**: SIGTERM; it says "stopped", no `demo_flood` sandbox or cgroup is left, and
   every durable log's chain verifies.

## Addendum, 2026-10-07 (evening), before the re-run: M31 survived

The first mutant run on `verify-2026-10-tests` killed 17 of the 19 new mutants. M25 survived as
predicted. **M31 survived, against the prediction.** Its log shows why: after the cut-off,
`demo_flood`'s sandbox "exited by itself (status 0)" one second later, because the runtime stops
when the mediator closes its channel (F30's fix). So step 2 passed with the kill removed, and the
supervisor's kill was tested only where something else already did its job.

The kill exists for an integration that does **not** stop by itself. `experiments/flood/demo_stubborn`
is `demo_flood` with one change: turning it on also blocks the event loop, so the runtime never sees
the channel close. `selftest_supervise` gains step 8: demo_stubborn is cut off, and its process and
cgroup must be gone within 15 s without "exited by itself".

**Predicted:** unmutated, step 8 passes; under M31 it fails at "its sandbox's process is gone". M32–M35
still killed. Run on the moved tag: all 27 suites twice, then M31–M35. If the flood thread cannot reach
the mediator while the event loop is blocked, there is no cut-off and step 8 fails unmutated; that
would be a fault in the test, fixed and stated.
