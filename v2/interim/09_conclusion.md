# 9 Conclusion

This project set out to test whether Home Assistant's community integrations, which today run with the full authority of the platform, can be confined without changing their code or the platform itself. It built a framework in which each integration runs in its own Linux sandbox, against a private and minimal copy of the platform, and reaches the household's installation only through a mediator that holds the one credential, decides each request against the permissions a person approved, and records the decision before acting on it.

The evaluation compared every integration confined and unconfined on the same Raspberry Pi 5, and each of its three assertions held. Confinement was effective: the two published attack techniques by a hostile integration succeeded without the framework and found nothing with it, and the project's own 39 attacks recovered neither planted secret. It was compatible: across 75 integrations from two samples of the community catalogue, no integration that loaded unconfined failed to load confined, and all thirteen integrations run end to end worked. And it was affordable: the device holds at least 17 sandboxes against an average need of about four, and the mediator runs about sixty times clear of realistic demand.

These results are bounded by attacks written within the project, by permissions written by hand, by an average rather than a distribution of integrations per installation, and by a single platform release. Within those bounds, the project shows that an integration's authority need not be total and invisible: it can be declared before installation, limited while the integration runs, and recorded each time it is used.
