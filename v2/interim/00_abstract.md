# Abstract

Home Assistant is an open-source platform that runs on a small computer inside the home and controls its lights, heating, alarms and door locks, with more than 669,000 installations reporting to its analytics. Its community integrations, the plug-in modules that connect it to devices and online services, ask for no permissions and run inside the platform with its full access, so an integration installed to show electricity prices could also read stored passwords or unlock the front door. This project designs, builds and evaluates a framework that confines each community integration without changing its code or the platform. Each integration runs in its own Linux sandbox, against a minimal private copy of the platform, and reaches the household's installation only through a separate mediator, which checks every request against permissions a person has approved and records each decision in a log that cannot be altered unnoticed. The framework was evaluated on a Raspberry Pi 5, comparing every integration with and without confinement. The two published attack techniques by a hostile integration succeeded against an ordinary installation and found nothing under confinement, and the project's own 39 attacks recovered no planted secret. Across 75 community integrations, none that loaded normally failed to load when confined, and thirteen worked confined end to end. The device holds at least 17 sandboxes, four times the average number of community integrations per installation. These results are bounded by attacks written within the project, permissions written by hand and a single platform release.

**Keywords:** Home Assistant; smart home security; sandboxing; least privilege; Internet of Things
