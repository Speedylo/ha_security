# 10 Future Work

The most important next step is an independent test of the security result. Every attack in the evaluation was written within the project, and the route out of the sandbox found by reading the code, which no automated test had detected, shows that builders miss what they did not imagine. A reviewer outside the project, attacking the framework without knowing its design in advance, is the only way to test the result against that gap.

The second step decides whether the framework could be adopted at all. The integrations' code is unchanged, but each still needs a permissions manifest, and no integration ships one today. Authors could add one themselves, since it changes no code; a manifest could be derived automatically by analysing an integration's source; or a curated collection could be maintained alongside the community store for integrations whose authors do not respond. Comparing the accuracy of derived manifests with hand-written ones would show which of these routes is practical.

The evidence itself can also be extended. Running a household's own integrations confined for several months would test the compatibility and cost results in daily use rather than in test runs, and repeating the compatibility runs automatically at each new platform release would show whether the results survive the platform's changes. A study with real users of the approval screen would test whether the person approving a permission understands what it allows, an assumption the evaluation could not examine.

Two risks lie beyond confinement. An integration may misuse a permission it legitimately holds, such as unlocking a door at three in the morning, and it may send household data to a service it is allowed to reach. A model trained on an integration's own decision record could hold an unusual action for a person's confirmation, in the spirit of ContexIoT's contextual prompts (Jia et al., 2017), provided the model can only delay or refuse an action and never grant one. The same record could also inform other households: each run is tied to the exact version of the integration that made it, so households could share verdicts on a version, such as whether anything it requested was refused. Without a central authority, however, an attacker can create enough fake participants to manufacture a good reputation (Douceur, 2002), so such sharing would be a separate project.

Finally, a lasting solution belongs to the platform. A permission check inside the platform's own process can be reached by the code it restricts (Corno & Mannella, 2022), so Home Assistant would need to place community integrations behind a process boundary itself. This project supplies the evidence such a change would need: what confinement costs, what a permission must express, and which threats it closes.
